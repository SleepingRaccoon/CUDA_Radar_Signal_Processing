# PC_v1 结果执行反馈

原理见 `PC_v1_math.md`，契约与计时口径见 `PC_v1_eng.md`。
记录格式固定：**假设 → 实测 → 结论 → 复现**。失败与被推翻的结论一并保留。

环境：CUDA 13.2 / driver 616.92 / RTX 3050 Laptop（sm_86, 4 GB）/ cupy 14.2.0，
GPU 未锁频（实测 SM 1500–1965 MHz / 显存 6001 MHz）。REPS = 100，取中位数。
分工：NumPy 版保正确，CuPy 版只保 GPU 初步正确，调优归 CUDA 版。

# 2 增益账：理论 vs RD 图实测

理论 \(G=N_sN_c(\operatorname{mean}w/\operatorname{rms}w)^2=120\times256\times2/3=20480=43.113\) dB；
输入每采样 SNR \(A^2/\sigma^2=0.01\)（−20 dB），理想输出峰值 SNR 23.113 dB。

100 个噪声种子取平均（rdmap 峰值功率 / 每格噪声平均功率）：

| 目标 | 落格偏移 | 理论 | 实测 | 差 |
| --- | --- | --- | --- | --- |
| 2000 m, +40 m/s | 0.489 bin | 21.753 dB | 21.638 dB | −0.115 dB |
| 4000 m, −50 m/s | 0.111 bin | 23.044 dB | 22.943 dB | −0.101 dB |

结论：公式成立。残差 −0.1 dB 与被忽略的距离走动同量级（两个目标在 CPI 内分别走 0.11 / 0.14 个距离格）。
单次运行不能用来核对增益——单个 RD 格的噪声起伏有 ±0.5 dB。

# 3 决策日志

**D1 九步版 → 库基线。**
假设：CuPy 不必与 CUDA 版步骤一一对应。
实测：九步显式版 1.449 ms（copy 1.031 + compute 0.418）；合并成 5 步库调用、去掉 `Nd == Nc` 时的
无谓补零、H2D/D2H 改 pinned 之后 0.767 ms。
结论：CuPy 定位改为「现成库能达到的最快值」，手写核留给 `PC_v1.cu`。

**D2 计时必须热身（DVFS）。**
假设：0.8 ms 量级的短负载会让 GPU 停在低时钟，读数偏慢。
实测：不热身 2.742 ms；热身 0.3 s 后 0.767–0.783 ms（差 3.5 倍）。空闲态显存时钟 405 MHz、
稳态 6001 MHz；SM 从 1500 升到 1965 MHz 时时间不变，说明瓶颈在显存不在 SM。
结论：计时区前置 `warm_up(0.3)` 并打印时钟；换卡或换电源计划要重新标定。

**D3 加窗与转置的顺序（推翻自己的结论）。**
假设：GPU 上「先乘后转」比「先转后乘」快 10%（来自孤立微基准）。
实测：加 300 轮热身后原位交替对比，两者相同（0.3104 / 0.3102 ms）；CPU 上只差约 5%，
真正有效的是原地乘（1.94 → 1.07 ms）。
结论：顺序不影响性能，按可读性选「先乘后转」。原 10% 的结论是热身不足的假象。

**D4 pinned 主机缓冲。**
假设：pageable 内存的 H2D/D2H 受驱动分页拷贝限制。
实测：H2D 0.370 → 0.254 ms、D2H 0.625 → 0.168 ms（3.4 → 12.5 GB/s）。
结论：copy 从 1.031 降到 0.445 ms；附带用 `memcpy2DAsync` 直接写进补零缓冲，省掉设备侧 pad 拷贝。

# 4 CUDA 版任务清单

CuPy 版到此冻结（只保正确性，不再调优）。下面这张表是交给 CUDA 版的目标清单。

nsys 实测（在 CuPy 版的 5 个逻辑步骤上各套一个 `cupyx.profiler.time_range`：
`nsys profile --trace=cuda,nvtx --stats=true python PC_v1_cupy.py`）：
一次迭代 = **9 个 kernel + 1 次 H2D(3.03 MB) + 1 次 D2H(2.10 MB)**。

| kernel | 每次迭代 | 时间 | 说明 |
| --- | --- | --- | --- |
| `vector_fft<2048>` | 2 | 93.6 µs | 距离维正/逆变换，cuFFT |
| `cupy_copy__complex64` | 3 | 52.9 µs | 转置 / fftshift / 拷贝 |
| `cupy_multiply`（乘 H） | 1 | 48.1 µs | |
| `cupy_true_divide` | 1 | 48.0 µs | `cp.fft.ifft` 的 1/N，跑在完整 `[Nc][N_fft]` 上 |
| `vector_fft<256>` | 1 | 25.6 µs | 慢时间维，cuFFT |
| `cupy_multiply`（加窗） | 1 | 24.2 µs | |
| 合计 | 9 | ~292 µs | 加发射开销即实测 compute 0.322 ms |

由此得到 CUDA 版要做的事：

- 把「1/N 缩放 + 截取 + 加窗 + 转置」融合成**一个核**：现在是 4 个 kernel、约 4 遍访存，
  融合后 1 个核 2 遍访存。
- 1/N 不要跑在完整的 `[Nc][N_fft]` 上——现在白缩放了会被截掉的列。
- `fftshift` 是纯索引重排，考虑折进输出索引或与下游合并。
- cuFFT 那 119 µs（37%）不动，当作上界。
- 另两条库层面实验：`N_fft` 2048 → 1536（省 25% 距离维 FFT）；`cufft.PlanNd` 的 strided
  batch 直接把 `[Nc][Nr]` 变换成 rd 布局（省掉转置，代价是跨步访存）。
- 出正式数字前锁频（`nvidia-smi -lgc`）并复测。
